Git history introduces all three files in [`d3d7d273aa74f92fe783ae3fd65300a12377b132`](https://github.com/matlus/Skills-and-Evals/commit/d3d7d273aa74f92fe783ae3fd65300a12377b132). The first two are the committed standard and more precise prompt definitions. The third explicitly requests tables first, exactly three findings, verification of numbers/comparisons against tables, and restriction to the two stated budget targets.

**Boundary:** The inspected saved result folders contain scorecards, `regraded_from.txt`, trial answers, event streams and grades. They contain no per-run prompt snapshot, prompt hash, suite snapshot or source revision manifest. The session event streams examined begin with session/thread metadata and model activity, rather than the complete initial user prompt. The scorecard's variant name identifies the label used, but cannot by itself prove which text occupied that prompt file at invocation. Therefore this index can verify the saved counts and point to the committed prompt definitions; it cannot independently certify a run-to-prompt-revision binding or reconstruct earlier prompt variants.

The need for exact batch links is concrete: [another saved Opus robust-tables-first scorecard](https://github.com/matlus/Skills-and-Evals/blob/5ec0b0a9bd4c9361cb059984675cd2e62352c699/results/pwi/expense_analysis/20261010T112630Z-regrade-claude_code-claude-opus-5-5-medium-39a815/scorecard.md) reports four trials and findings 2/4. It is not one of O1/O4, and should not be substituted for them merely because its variant name matches or its folder name sorts later. No claim about its earlier/later prompt text is established here.
